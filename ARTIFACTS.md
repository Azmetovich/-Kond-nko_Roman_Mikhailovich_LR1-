# ARTIFACTS.md

## 1. Введение

Документ содержит перечень основных артефактов курсового проекта Pizza и правила взаимодействия между его модулями. Он используется для понимания структуры проекта, назначения файлов, правил их хранения в Git и порядка обмена данными между частями приложения.

Проект представляет собой WPF-приложение на C# для работы пиццерии. Приложение использует Entity Framework 6 и базу данных Microsoft SQL Server. Для формирования PDF-чеков применяются библиотеки PDFsharp и QRCoder.

### Классификация по этапам жизненного цикла

**Проектирование:** README.md, DBPizza.edmx, DBPizza.edmx.diagram, файлы решения и проекта.

**Разработка:** файлы C# и XAML, модели Entity Framework, App.config, packages.config, ресурсы.

**Тестирование:** отладочная сборка в bin/Debug, PDB-файлы и временные результаты сборки. В проекте отдельного тестового проекта нет.

**Поставка:** Pizza.exe, необходимые DLL и файл Pizza.exe.config из каталога сборки. Эти файлы создаются автоматически и в Git не хранятся.

**Эксплуатация:** App.config и рабочая база данных, с которой взаимодействует приложение.

Каталоги bin/, obj/, packages/ и .vs/ не должны попадать в репозиторий. В проекте они исключены правилами .gitignore.

## 3. Протоколы взаимодействия

### Протокол 1. Представление — модуль работы с данными

**Участники:** окна из каталога Win/, App.Context, PizzaParovozovEntities.

**Назначение:** получение, добавление, изменение и удаление данных приложения.

**Описание:** окна обращаются к статическому объекту `App.Context`. Чтение выполняется через коллекции Entity Framework, например `Products`, `Users`, `Employees`, `Carts`, `Orders`, `OrderProducts`, `WorkSchedules`. Для добавления и удаления используются методы `Add()` и `Remove()`, после изменения вызывается `SaveChanges()`.

**Формат данных:** объекты C# классов Entity Framework.

**Ограничения:** операции выполняются через один общий контекст `PizzaParovozovEntities`; ошибки работы с БД обрабатываются в окнах приложения.

### Протокол 2. Представление — модели данных

**Участники:** модуль представления и классы `User`, `Employee`, `Product`, `Ingredient`, `Cart`, `Order`, `OrderProduct`, `ProductIngredient`, `WorkSchedule`, а также вспомогательная модель `CatalogProduct`.

**Назначение:** передача данных между интерфейсом и логикой приложения.

**Описание:** данные передаются как C#-объекты. Окна получают сущности из базы данных, считывают их свойства и формируют данные для элементов интерфейса. Для каталога и корзины используется объект `CatalogProduct`, содержащий идентификатор, название, описание, цену, состав и путь к изображению.

**Формат данных:** объекты C#, коллекции `List<T>`, строки, числа, `DateTime` и другие типы .NET.

### Протокол 3. Авторизация и хранение текущего пользователя

**Участники:** `MainWindow`, `App`, `User`, `AdminWindow`, `WorkerWindow`.

**Назначение:** проверка учётных данных и определение роли пользователя.

**Описание:** `MainWindow` ищет пользователя в `App.Context.Users` по логину и паролю. После успешной авторизации объект сохраняется в `App.CurrentUser`. При `IdRole = 1` открывается окно администратора, при `IdRole = 2` — окно сотрудника.

**Формат данных:** объект `User`.

### Протокол 4. Работа с корзиной и заказом

**Участники:** `CatalogWindow`, `CartWindow`, модели `Cart`, `Product`, `Order`, `OrderProduct`, `Employee`.

**Назначение:** передача выбранных товаров из каталога в корзину и создание заказа.

**Описание:** `CatalogWindow` создаёт объект `Cart` с идентификаторами пользователя и товара. `CartWindow` загружает позиции текущего пользователя, рассчитывает общую стоимость, создаёт `Order` и связанные записи `OrderProduct`, после чего очищает корзину.

**Формат данных:** объекты C# Entity Framework и `List<CatalogProduct>`.

### Протокол 5. Формирование PDF-чека

**Участники:** `CartWindow`, модели заказа, библиотеки PDFsharp и QRCoder.

**Назначение:** создание и сохранение чека после оформления покупки.

**Описание:** метод `GenerateReceiptPdf` получает путь к файлу, номер чека, сотрудника, список товаров, итоговую стоимость и строку QR-кода. PDFsharp создаёт PDF-документ, а QRCoder формирует QR-код, который добавляется в чек.

**Формат данных:** объекты C#, `List<CatalogProduct>`, строковые значения, PDF-файл и изображение QR-кода.

### Протокол 6. Работа с рабочим графиком

**Участники:** `WorkSchedule`, `Employee`, модель `WorkSchedule`, `App.Context`.

**Назначение:** загрузка расписания сотрудников и добавление новой записи графика.

**Описание:** текущий сотрудник определяется по `App.CurrentUser.IdUser`. Расписание загружается из `App.Context.WorkSchedules`. Новая запись создаётся как объект модели `WorkSchedule`, добавляется в контекст и сохраняется методом `SaveChanges()`.

**Формат данных:** объекты C#, дата и время.

### События

Специальная система публикации и подписки на события между модулями в проекте не используется. Основное взаимодействие с интерфейсом выполняется стандартными событиями WPF, например `Click`, обработчики которых имеют имена `BtnLogin_Click`, `BtnSave_Click`, `BtnDelete_Click`, `BtnBack_Click` и т.д. После действий пользователя обработчик вызывает нужную операцию с данными или открывает другое окно.

## 4. Соглашения об именовании и версионировании

В проекте используются следующие правила:

- классы и окна именуются в PascalCase: `MainWindow`, `CatalogWindow`, `Product`, `WorkSchedule`;
- методы именуются в PascalCase: `LoadProducts`, `LoadCart`, `LoadOrders`, `GenerateReceiptPdf`;
- обработчики событий содержат имя элемента и событие: `BtnLogin_Click`, `BtnSave_Click`, `BtnBack_Click`;
- файлы окон имеют одинаковые базовые имена для разметки и кода: `CartWindow.xaml` и `CartWindow.xaml.cs`;
- пространство имён приложения — `Pizza`, модели базы данных находятся в `Pizza.Entity`;
- имена сущностей используются в единственном числе, а коллекции контекста — во множественном числе;
- сообщения коммитов должны кратко описывать выполненное изменение;
- основная версия сборки проекта сейчас указана как `1.0.0.0`;
- для дальнейшего версионирования может применяться SemVer: `MAJOR.MINOR.PATCH`, например `1.0.0`, `1.1.0`, `1.1.1`.

## 5. Заключение

В проекте Pizza определены исходные, конфигурационные, проектные, производные и вспомогательные артефакты. Исходный код, файлы проекта, конфигурация и документация хранятся в Git, а временные файлы Visual Studio, NuGet-пакеты и результаты сборки исключаются через `.gitignore`. Основное взаимодействие модулей выполняется через объекты C#, общий контекст Entity Framework `App.Context` и стандартные события WPF. Описанные правила позволяют понять структуру проекта и порядок взаимодействия его частей перед дальнейшей интеграцией и разработкой.
